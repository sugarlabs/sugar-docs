Contributing
============

Sugar Labs uses the **pull request model** for all contributions.  
If you are new to GitHub, see [GitHub's help on pull requests](https://help.github.com/articles/using-pull-requests).

In brief, you will:

* on GitHub, find and **fork** the source repository;
* on your computer, **clone** your forked repository;
* create a **new branch** for your changes;
* make your changes and **commit** them;
* **push** your branch and submit a **pull request**; and
* go through the **review process** until your pull request is merged.

Please note:

* There is **no need to ask permission** to work on an issue.
* Before starting, check for existing pull requests linked to the issue you are addressing.
* If there are none, assume nobody is working on it and proceed.
* Test your changes before submitting a pull request.
* Mention the **issue number in the pull request**, but **not** in the commit message.

These practices encourage healthy collaboration and competition of ideas.  
Sugar Labs is a **meritocracy**.
